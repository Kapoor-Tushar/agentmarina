What is AgentMarina?

AgentMarina is a framework-neutral, self-hosted platform that wraps the AI agent you already have and runs it as a governed, scalable service on your own infrastructure. It adds the parts a demo agent lacks: durable sessions, a queue, autoscaling, tenant isolation, guardrails, tracing and evaluations.

It is a self-hosted alternative to managed agent runtimes such as AWS Bedrock AgentCore, Google Vertex AI Agent Engine and Azure AI Foundry Agent Service, without tying your sessions, memory, identity and traces to one cloud.

Status: built and tested, code private for now. An MIT-licensed open-source release is planned when the GitHub repository reaches 1,000 stars.

Why running AI agents in production is hard

A demo agent is a loop around a model. A production agent is a distributed system with an unusually hostile workload.

State that outlives the process

Per-turn checkpoints, restore on another host and exactly-once turns, so a crash or client retry never loses a conversation or runs a refund twice.

Long, bursty, I/O-bound requests

Turns last 2 to 60 seconds. You need session-aware routing, backpressure, fair queuing and autoscaling that never kills a host holding a live conversation.

Isolation versus density

Explicit isolation tiers and provable tenant separation across ids, caches, memory and logs.

Sensitive data in the loop

PII and secrets in prompts and tool results, including values split across streamed chunks.

A new attack surface

Prompt injection, poisoned tool descriptions, SSRF through URL-fetching tools and confused-deputy credentials.

Observability, quality and supply chain

One trace model across frameworks, a CI gate for quality regressions, and signed, scanned images.

What AgentMarina gives you

One agent, three protocols

The same process and session answers plain HTTP, A2A (agent-to-agent) and MCP (Model Context Protocol).

Bring any agent

Google ADK, LangGraph, Strands, OpenAI Agents SDK, PydanticAI, CrewAI, plain Python, or a remote agent in any language. No rewrite.

Sessions that scale

Many conversations per host, sticky routing, a durable queue, scale-to-zero, canary rollouts and per-turn checkpoints.

Multi-tenant by design

Tenant isolation at every layer and per-tenant quotas. The tenant always comes from a verified credential.

Memory you choose

Short-term and long-term memory (facts, summaries, vectors, episodes, knowledge graph) on SQLite, Postgres or MongoDB.

Tool and model gateway

MCP servers, OpenAPI services, SQL and Lambda behind policy; model proxy with fallbacks, budgets, streaming and caching.

Guardrails that do not break the agent

PII and secret detection with reversible pseudonymization, prompt-injection checks and Cedar policy.

OpenTelemetry observability

A trace for every LLM and tool call in every framework, sent to the backend you already use.

Evaluations and registry

LLM judge with calibration, versioned datasets, a CI quality gate, and an approved catalog of agents, tools and models.

Trusted supply chain

Hardened image, vulnerability scan gate, Sigstore cosign signing and Kyverno admission control.

How it works

  1. Package. Add a small manifest next to your agent. AgentMarina builds a hardened, non-root image.
  2. Deploy. Render the deployment for your platform and apply it. A router fronts a pool of agent hosts that scale from zero.
  3. Call. Your app, an MCP client or another agent calls one endpoint. The router authenticates, keeps the conversation on the right host, queues under load and applies policy on the way in and out.
  4. Operate. Watch traces, run evaluations, roll out to a slice of traffic and roll back automatically if it misbehaves.

Frequently asked questions

What is AgentMarina?

A self-hosted runtime that wraps the AI agent you already have and runs it as a governed, scalable service on your own infrastructure.

Which agent frameworks are supported?

Google ADK, LangGraph, Strands, OpenAI Agents SDK, PydanticAI, CrewAI and plain Python, plus any remote agent over A2A, MCP, an OpenAI-compatible API or HTTP.

Where can I run it?

Kubernetes (EKS, GKE, AKS, k3s, kind, on-prem), Amazon ECS, Google Cloud Run, Azure Container Apps, and VMs or bare metal.

Is it open source?

An MIT-licensed release is planned when the GitHub repository reaches 1,000 stars.

How is this different from running my agent in a container?

A container gives you a process. AgentMarina adds sessions across many hosts, queueing and autoscaling, tenant isolation, memory, guardrails, tracing, evaluations and a signed supply chain.

Does my data leave my infrastructure?

AgentMarina keeps its state in your database and queue. Model calls go to the provider you configure, and guardrails can pseudonymize sensitive values before they reach it.
